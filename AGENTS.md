# Release Update Guide

This document outlines the steps to update the Linux build when a new Windows version of MiniMax Agent / MiniMax Code is released.

## Maintainer

- **GitHub:** unn-Known1
- **Email:** ptelgm.yt@gmail.com

## Supported Targets

| Target | Package | Status |
|---|---|---|
| Debian / Ubuntu / Mint (amd64) | `.deb` | First-class, automated via `release_new.yml` |
| **Cachy OS** (amd64) | `.pkg.tar.zst` | **First-class, automated via `release_new.yml` (Cachy OS job)** |
| Arch / Manjaro / EndeavourOS (amd64) | `.pkg.tar.zst` | First-class, same artifact as Cachy OS |
| AUR | source-only | AUR-ready PKGBUILD; AUR submission is manual |

## Automated Release (Recommended)

Use the GitHub Actions workflow `release_new.yml`. It now builds **two packages** in parallel:

1. `.deb` for Debian / Ubuntu / Mint (unchanged)
2. `.pkg.tar.zst` for Cachy OS / Arch / Manjaro / EndeavourOS (new)

The workflow will:

- Download the Windows `.exe` from the CDN (`https://file.cdn.minimax.io/public/minimax-agent-prod/release/MiniMax%20Code%20Setup%<VERSION>.exe`)
- Extract and copy resources
- Update all version references
- Build the `.deb` package
- Build the Cachy OS package (in a Docker `archlinux:latest` container, with the host's Cachy OS detected and `--v3` applied when applicable)
- Generate `.SRCINFO` from the PKGBUILD
- Create a Git tag and GitHub Release
- Upload **both** packages to the release
- Create a GitHub issue if the build fails

**Workflow file:** `.github/workflows/release_new.yml`

**CDN URL pattern:** `https://file.cdn.minimax.io/public/minimax-agent-prod/release/MiniMax%20Code%20Setup%<VERSION>.exe`

**How to trigger:**
1. Go to **Actions** → **Build and Release MiniMax Agent Linux** → **Run workflow**
2. Enter version (e.g., `3.0.54`)
3. Optionally provide a custom EXE URL (auto-detected from the CDN if not provided)
4. Click **Run workflow**

## Manual Release Process (Legacy)

This section covers doing the release by hand if the CI is down.

### Prerequisites

- Linux system with `dpkg-deb`, `fakeroot`, `npm`, `npx`, and `7z` (p7zip-full) installed
- For Cachy OS / Arch: `base-devel` (provides `makepkg`)
- Docker (optional, for cross-building the Cachy OS package from any host)
- Access to the Windows `.exe` release URL
- Git access to this repository

### Step-by-Step Release Process

#### 1. Download the Windows `.exe` Release

```bash
mkdir -p /tmp/minimax-extract
cd /tmp/minimax-extract
curl -fsSL -o "MiniMax Code Setup <VERSION>.exe" "<EXE_URL>"
```

#### 2. Extract the `.exe` Archive

NSIS installers can be extracted with 7z:

```bash
mkdir -p extracted
7z x -oextracted "MiniMax Code Setup <VERSION>.exe"
```

Then extract the app archive (use `app-64.7z` for amd64):

```bash
mkdir -p app-64
7z x -oapp-64 extracted/\$PLUGINSDIR/app-64.7z
```

#### 3. Update Version References

Update the version in all relevant files:

| File | Field to Update |
|------|----------------|
| `build.sh` | `VERSION="X.X.X"` |
| `setup.sh` | `VERSION="X.X.X"` |
| `releases/download.sh` | `VERSION`, `GITHUB_URL` |
| `releases/download-cachyos.sh` | (none — version is auto-detected from the latest release tag) |
| `README.md` | Version badge, download URLs, install commands, date |
| `INSTALL.md` | Install command |
| `CONTRIBUTING.md` | alien command example |
| `cachyos/PKGBUILD` | `pkgver=`, `pkgrel=` |
| `cachyos/.SRCINFO` | regenerated by `makepkg --printsrcinfo > .SRCINFO` |
| `linux-build/DEBIAN/control` | `Version: X.X.X` |
| `linux-build/opt/minimax-agent/resources/resources/daemon/package.json` | `version` |

**Important:** when bumping `pkgver` in `cachyos/PKGBUILD`, always regenerate `.SRCINFO` from it — never hand-edit. Use:

```bash
cd cachyos
makepkg --printsrcinfo > .SRCINFO
```

#### 4. Update Linux Build Resources

Copy the new files from the extracted Windows release (this is the same for both the .deb and the Cachy OS package — they share the `linux-build/` tree):

```bash
# app.asar (main application code)
cp /tmp/minimax-extract/app-64/resources/app.asar \
   linux-build/opt/minimax-agent/resources/app.asar

# app.asar.unpacked (native modules)
rm -rf linux-build/opt/minimax-agent/resources/app.asar.unpacked
cp -r /tmp/minimax-extract/app-64/resources/app.asar.unpacked \
      linux-build/opt/minimax-agent/resources/app.asar.unpacked

# Update tray icons and resources
cp /tmp/minimax-extract/app-64/resources/app-update.yml \
   linux-build/opt/minimax-agent/resources/app-update.yml
cp /tmp/minimax-extract/app-64/resources/resources/icon.ico \
   linux-build/opt/minimax-agent/resources/resources/icon.ico
cp /tmp/minimax-extract/app-64/resources/resources/tray.ico \
   linux-build/opt/minimax-agent/resources/resources/tray.ico
cp /tmp/minimax-extract/app-64/resources/resources/tray.png \
   linux-build/opt/minimax-agent/resources/resources/tray.png
cp /tmp/minimax-extract/app-64/resources/resources/trayTemplate@2x.png \
   linux-build/opt/minimax-agent/resources/resources/trayTemplate@2x.png
cp /tmp/minimax-extract/app-64/resources/resources/trayTemplate.png \
   linux-build/opt/minimax-agent/resources/resources/trayTemplate.png
```

#### 5a. Build the `.deb` Package

```bash
cd /root/minimax-agent-linux
sudo ./build.sh
```

The script will:
- Check build dependencies
- Rebuild `better-sqlite3` native module for Electron ABI
- Build the `.deb` package in `output/`
- Verify the package and daemon entry point

#### 5b. Build the Cachy OS / Arch Package

On a Cachy OS or Arch host:
```bash
./build-cachyos.sh
```

Or in a Docker container from any host:
```bash
./build-cachyos.sh --docker
```

Or to force x86-64-v3 optimization (matches Cachy OS's default CFLAGS):
```bash
./build-cachyos.sh --v3
```

The script will:
- Build a source tarball from the working tree
- Run `makepkg` (or `makepkg` inside Docker) with the right flags
- Drop the resulting `.pkg.tar.zst` in `releases/`
- Print install instructions

#### 6. Copy to Releases

```bash
cp output/minimax-agent_<VERSION>_amd64.deb releases/
cp releases/minimax-agent-<VERSION>-1-x86_64.pkg.tar.zst releases/  # already there, but harmless
# Generate a SHA256SUMS file so the Cachy OS installer can verify
( cd releases && sha256sum minimax-agent-* > SHA256SUMS )
```

#### 7. Create Git Tag and Push

```bash
git add -A
git commit -m "Release v<VERSION>"
git tag -a v<VERSION> -m "Release v<VERSION>"
git push origin main --tags
```

#### 8. Create GitHub Release

```bash
gh release create v<VERSION> \
    releases/minimax-agent_<VERSION>_amd64.deb \
    releases/minimax-agent-<VERSION>-1-x86_64.pkg.tar.zst \
    releases/SHA256SUMS \
    --title "v<VERSION>" \
    --notes "Release v<VERSION> - Updated from Windows <VERSION>"
```

#### 9. Clean Up

```bash
rm -rf /tmp/minimax-extract
```

## Cachy OS / Arch Packaging Deep Dive

### Why a real PKGBUILD instead of `debtap`

The original `build-arch.sh` used `debtap` to convert the `.deb` to an Arch package. This works but produces a "downstream" package that:

- Doesn't follow Arch packaging conventions
- Has wrong dependency names (Debian → Arch translation is lossy)
- Has no `install` script
- Misses the AUR submission path
- Doesn't take advantage of Cachy OS's x86-64-v3 CFLAGS

The new `cachyos/PKGBUILD` is a real, AUR-ready package definition. It:

- Lists Arch-native dependencies (mapped from `linux-build/DEBIAN/control`)
- Has a proper `install` script (`cachyos/minimax-agent.install`) that mirrors the `.deb`'s `postinst`/`prerm`
- Detects Cachy OS at build time and applies x86-64-v3 CFLAGS
- Generates `.SRCINFO` for AUR
- Can be built by `makepkg` directly, or via the wrapper `build-cachyos.sh`

### PKGBUILD version bumps

`pkgver` should be bumped in lockstep with `VERSION` in `build.sh` / `setup.sh`. `pkgrel` should reset to `1` for each new `pkgver`; bump it (`2`, `3`, ...) for a re-build of the same upstream version (e.g., PKGBUILD-only fixes).

After every `pkgver` or `pkgrel` change, regenerate `.SRCINFO`:

```bash
cd cachyos
makepkg --printsrcinfo > .SRCINFO
git add PKGBUILD .SRCINFO
```

After dependency changes, refresh the `sha256sums`:

```bash
cd cachyos
updpkgsums
```

### AUR submission

The AUR workflow is:

```bash
git clone ssh://aur@aur.archlinux.org/minimax-agent.git aur-minimax-agent
cp cachyos/PKGBUILD cachyos/.SRCINFO cachyos/minimax-agent.install aur-minimax-agent/
cd aur-minimax-agent
makepkg --printsrcinfo > .SRCINFO     # ensure freshness
git add -A
git commit -m "upgpkg: minimax-agent <version>"
git push
```

> Before the first AUR push, request ownership of the `minimax-agent` package on the AUR. See https://aur.archlinux.org/ for the procedure.

### Cachy OS–specific build flags

Cachy OS targets x86-64-v3 (Haswell+) by default. The PKGBUILD's `prepare()` function probes for v3 support and applies the right CFLAGS for any in-build compilation (e.g., the `npm rebuild` triggered by `minimax-agent.install`). To force v3 even on non-v3 hosts (e.g., when cross-building in CI on a non-Cachy host), use `./build-cachyos.sh --v3`.

## Key Files Reference

| Path | Purpose |
|------|---------|
| `linux-build/DEBIAN/control` | Debian package metadata (name, version, dependencies) |
| `linux-build/DEBIAN/postinst` | Debian post-install script (permissions, protocol handlers, daemon setup) |
| `linux-build/DEBIAN/prerm` | Debian pre-remove script (cleanup systemd units) |
| `linux-build/usr/bin/minimax-agent` | Application launcher script |
| `linux-build/usr/share/applications/minimax-agent.desktop` | Desktop integration file |
| `linux-build/opt/minimax-agent/resources/app.asar` | Main Electron application |
| `linux-build/opt/minimax-agent/resources/app.asar.unpacked/` | Native Node.js modules |
| `build.sh` | Debian build script |
| `setup.sh` | Post-install setup script (downloads Electron runtime) |
| `cachyos/PKGBUILD` | Arch / Cachy OS package definition |
| `cachyos/minimax-agent.install` | pacman install / upgrade / remove hooks |
| `cachyos/.SRCINFO` | AUR manifest (regenerate with `makepkg --printsrcinfo`) |
| `build-cachyos.sh` | Wrapper that builds the PKGBUILD (host or Docker) |
| `releases/download.sh` | One-shot installer for Debian users |
| `releases/download-cachyos.sh` | One-shot installer for Cachy OS / Arch users |

## Native Modules

The following native modules are bundled in `app.asar.unpacked`:

- `better-sqlite3` — SQLite database (rebuilt for Electron ABI during build, and again at install time against the host's Node.js)
- `node-pty` — Terminal emulation
- `@nut-tree/libnut-linux` — Screen automation
- `clipboardy` — Clipboard access
- `jszip` — ZIP archive handling

## Electron Version

The build targets Electron `v33.2.0`. The `setup.sh` script (Debian) downloads this runtime during installation. The Cachy OS package does the same — the `package()` function only stages the directory; the Electron binary is downloaded by the user with `setup.sh` if they want, or kept as a downloaded-from-network runtime that the package itself sets up via the install hook.

> Note: bundling Electron directly into the `.pkg.tar.zst` is a deliberate trade-off. A future improvement is to switch to depending on the system `electron` package (Arch has it), which would shrink the package significantly. Track this in the project issues.

## Troubleshooting

### Build fails with missing tools
```bash
sudo apt install dpkg-dev fakeroot npm npx
```

For the Cachy OS build:
```bash
sudo pacman -S base-devel
```

### better-sqlite3 rebuild fails
```bash
# Debian
cd linux-build/opt/minimax-agent/resources/app.asar.unpacked/node_modules/better-sqlite3
npm rebuild

# Cachy OS / Arch
cd /opt/minimax-agent/resources/resources/daemon
npm rebuild
```

### `.deb` package is corrupt
Verify the package:
```bash
dpkg-deb -I releases/minimax-agent_<VERSION>_amd64.deb
dpkg-deb -c releases/minimax-agent_<VERSION>_amd64.deb | head -20
```

### `.pkg.tar.zst` package is corrupt
Verify the package:
```bash
pacman -Qip releases/minimax-agent-<VERSION>-1-x86_64.pkg.tar.zst
pacman -Qlp releases/minimax-agent-<VERSION>-1-x86_64.pkg.tar.zst | head -20
```

### AUR `.SRCINFO` is stale
```bash
cd cachyos
makepkg --printsrcinfo > .SRCINFO
git diff .SRCINFO
```
